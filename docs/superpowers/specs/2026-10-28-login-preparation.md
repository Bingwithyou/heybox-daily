# 登录准备并行与一次性令牌进程预热

2026-10-28 用户批准两项方案的实现、验证、生产部署及 push。

## 目标与证据

降低发码请求的固定等待，保留现有短信、人机验证、设备隔离及失败恢复语义。VPS 隔离测量中，依赖加载约 0.53 秒、指纹生成器初始化约 0.19 秒，新指纹生成仅 3–5 ms。最近一次实际登录中 Worker 到 DO 首次调用的差额约 1.14 秒，后续验证约 51 ms；差额包含路由、激活等未分别测量的部分。

## 批准的行为

1. VPS 在有容量时保留一个已加载依赖及指纹生成器的子进程。请求到来后才下载并核验 SDK、生成新指纹、创建新 DOM 和生成新令牌；子进程只服务一次请求，然后退出。预热与运行中的子进程合计最多 4 个，现有 FIFO 排队限制保持不变。预热约增加 165 MiB 空闲内存，不共享账号信息、DOM、指纹或令牌。
2. 执行 Worker 为每次发码创建独立挑战 ID，同时调用该 DO 的初始化接口和 VPS 令牌接口。两项都成功且尚未取消后，调用同一 DO 的 begin，由 DO 持久化 busy 状态并发送短信。预备调用不发送短信、不存手机号或令牌、不创建保活循环。每次发码增加一次内部 DO 请求。
3. 超时、取消、预热进程崩溃及服务停止均有清理；预热失败不无限高速重启，当前请求不自动重试生成或发送短信。DO 重建后仍执行持久化状态恢复，保持 browser binding、过期、busy 和凭据加密规则。
4. 保留各段数值计时及随机请求关联 ID；不记录令牌、手机号、验证码或内部载荷。新增准备阶段计时用于证明并行发生。新调用流程不向公共 API 开放令牌输入。

## 兼容与回滚

不改变公共登录 API 或数据库。VPS 通过 `TOKEN_PREWARM=false` 关闭空闲预热；执行 Worker 通过 `LOGIN_PREPARE_PARALLEL=false` 回到原串行路径。默认启用已批准方案，配置示例明确开关。部署前保留前一个容器镜像和 Worker version ID，可分别回滚。

## 验收

- 预热进程不提前执行 SDK 或访问上游；一次使用后退出；新请求使用独立进程。
- 进程总数不超过 4；取消、超时、崩溃、关闭不遗留子进程或排队请求。
- DO 初始化与令牌请求确实重叠；任一失败或取消不发短信；成功仅一次 begin。
- workerd 中验证真实 DO 初始化、重建、加密存储及模拟短信链路；所有模拟上游结果明确标记。
- 生产部署验证真实令牌生成、配置/版本及服务健康，记录固定开销和耗时。真实发码/登录仅使用已有明确账号授权，不将令牌成功或模拟测试当作真实登录成功。

## 成本

VPS 内存增加；每次发码多一次 DO 请求。DO 活跃时长变化需实测，不能预先承诺账单为零或一定下降。
