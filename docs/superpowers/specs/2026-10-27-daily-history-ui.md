# 每日任务与历史记录

## 已批准范围

2026-10-27 用户确认第二版 UI 预览并要求实现后本地验收。

- 每日任务页将标题「每日任务」、北京时间日期、自动任务开关和下一次执行合成桌面端一行，窄屏自然换行。移除完成计数及重复的固定执行时间说明。
- 保留任务、状态、核验时间三列；不展示各项任务的预期奖励。
- 实际执行且核验完成显示「已完成」；已完成而未执行显示「已跳过」。跳过不改变任务已经完成的业务语义，重试不能覆盖当天曾经执行的事实。
- 底部仅汇总实际 EXP、H 币、盒电增量，使用 APP 原始小图标（16px）。盒电读取任务接口 `user.battery`，保存执行前后的差值。
- 独立 `/history` 页面，标题及导航为「历史记录」，列为日期、任务类型、状态、实际收益。包含今天，当前账号最近 15 条、日期倒序，沿用 30 天清理规则。
- 四项都明确跳过且任务完成时，历史显示「已跳过」；其他成功任务显示「已完成」。旧记录不倒推跳过，缺失收益显示 `—`。
- 本次不扩大后台调度模型或加入未来任务类型；历史接口返回任务类型字段以便后续扩展。保留当前仓库其他活动相关改动。
- 仅本地实现和预览，不 commit、push 或部署。

## 数据及兼容

- 核心任务返回及 runner 结果新增可选 `execution`：按四项任务 ID 记录 `executed` / `skipped`。在真实执行/跳过分支采集，不能根据奖励为零推断。
- 快照新增可选 `battery`，结果新增可选 `batteryDelta`。缺失或无效余额保持未知。重试累计盒电差值；任一尝试缺失增量时，总量保持未知。
- 持久化继续使用现有 jobs.result JSON，不迁移表结构。旧 runner 和旧记录均可读取。
- 重试合并保留 `executed`；旧尝试未记录执行情况时，不将后续跳过标记解释为整天从未执行。
- 新历史 API 复用账号权限与数据库查询，当前类型 `daily` / 名称「每日任务」。`/history` 和尾斜杠路径与任务页一样要求登录、noindex。
