# Linux 短信登录

增加独立登录容器，在命令行完成手机号和验证码登录；首次或重新登录时运行 Chromium，日常任务保持轻量镜像，不增加网页。实现后在 Linux ARM64 VPS 验证完整流程。

## 已核实的依据

- 空白 Linux Chromium 访问小黑盒官网，官方 SDK 可生成设备令牌；不读取手机、ADB 或旧账号 Cookie。
- VPS 上使用全新设备 ID、空账号和新令牌，短信发送、验证码登录均成功，新 `pkey` 被原生签到和 APP WebView 任务接口接受。
- 浏览器只负责初始化令牌。退出后，不含浏览器的日常镜像可加载保存的配置并执行任务。
- VPS 暴露了 `cap_drop: ALL` 与宿主机 `600` 配置文件的权限冲突。保留只读挂载和根文件系统，恢复 `DAC_OVERRIDE` 后已通过实际 Compose 运行验证。

## 实现范围

- 新增 `login` 命令和 Compose `login` 服务；手机号、验证码通过标准输入交互，不作为命令行参数。
- 每次登录获取独立令牌、生成设备 ID；请求使用当前已经验证的 APP 版本、原生签名和手机号 RSA 加密。
- 短信只按用户触发发送一次，不自动重发；失败给出明确错误，不绕过服务端要求的额外验证。
- 登录响应通过账号字段校验，并能读取原生签到状态和任务列表后，才原子替换配置。任何失败均保留原配置。
- 配置维持现有格式及 `600` 文件权限；不保存手机号或验证码，不在日志打印凭据。
- 日常 `check`、`run` 不加载 Playwright，不包含 Chromium。现有签名资源准备流程继续兼容；本轮不承诺自动下载 APK。
- README 更新为资源准备、服务器短信登录、运行三个步骤，保留已批准的风格和赞助部分。

## 关键取舍与边界

登录镜像包含 Chromium，体积会增加；将其独立出来可避免每日任务承担浏览器依赖。令牌初始化依赖官网及其 SDK，失败时停止，不用旧设备令牌冒充空白初始化。已有账号无需长期连接手机，但仍需要接收登录短信。当前日期已签到，首次未签到日奖励不在本次已验证结论内。

## 验收与交付

保留已有回归测试，增加协议参数、无凭据初始化、失败不覆盖、原子写入权限和交互流程测试。两个镜像均可构建；VPS 正式命令可登录并由轻量服务读取、运行。确认仓库内无账号凭据、私有资源和测试抓包后，使用仓库级 GitHub 身份提交并推送已授权分支，检查 CI。
