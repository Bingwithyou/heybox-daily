# Cloudflare 执行端迁移

用户于 2026-10-28 明确批准迁移：VPS 只保留登录设备令牌 SDK，其余每日任务、活动和登录流程迁到 Cloudflare。每日任务从 8 并发起步，配置可调整；按排队时间、上游限流与失败率决定后续调整，本次不自动加压。已批准创建必要资源、分阶段切换并验证；不包含 Git 提交、推送、worktree 或无关服务变更。

## 架构与合同

- 新增独立 `apps/executor` Worker，使用 `nodejs_compat`、D1、Queues 和 SQLite Durable Objects。网站通过 Service Binding 调用，不公开执行 Worker。凭据密钥只在执行端；现有密文、网站登录会话、页面/API 返回合同保持兼容。
- 每日任务消息只包含任务 ID 和投递标识，不含凭据。D1 保留账号/日期唯一性、原子领取、同账号租约、版本检查、最多 3 次业务尝试和跨日取消。新增投递标记及索引形成 outbox；发送失败、发送后回写失败、重复投递和租约过期均能恢复。任务完成并持久化结果后确认消息；队列消费者每批 1 条，初始最多 8 并发。后台扫描只查询索引上的待投递记录，使用每分钟恢复扫描和已有每日调度。
- 每日任务继续调用已有签名、分享加密和 `runDaily`。以可取消的请求和等待替代子进程超时，单次业务操作最多 4 分钟。仅对实际观察到的结果回写，不将失败或不明状态记录为成功。
- 活动列表、详情、关注与参与迁入执行 Worker。Durable Object 协调全局最多 4 路活动操作及同账号互斥；短期租约、过期清理与操作截止时间一起保证中断后可恢复。保留既有授权关注列表、参与前读取及结果确认流程。
- 每个登录挑战对应独立 Durable Object，取消验证阶段全局 4 并发和单进程 100 个挑战限制。保存加密的临时手机号、配置、阶段、验证码（仅验证码触发人机验证时）、尝试计数及票据哈希。有效期 5 分钟；alarm 清理，无空闲内存定时器。上游操作前持久化占用和尝试状态，同一挑战禁止并发；中断导致状态不明时失败关闭，不能自动重发短信。保留浏览器绑定和短信/IP 频率限制。
- VPS 独立设备令牌服务只接受已认证的令牌生成请求，不接收手机号、验证码或已登录凭据。SDK 初始最多 4 并发，增加有上限、有超时的短队列。验证成功后撤销旧 runner 的线上工作与凭据密钥配置；保留受控回滚备份。

## 已完成的设计核对

此前 workerd 离线验证已确认签名、加密、每日任务和活动核心流程兼容；登录 SDK 依赖 jsdom/node:vm，保留 Node。Queues 至少投递一次，因此不能用消息确认代替 D1 租约。DO 的内存定时器会阻止休眠，使用持久化状态和 alarm。异步 I/O 会交错，不能仅凭 DO 单线程假定不会并发。Web/SDK/队列切换时须阻止两套执行端同时领取同一业务任务；数据库和凭据格式不做破坏性迁移。

## 容量与观测

613 个正常账号约 18,390 次任务/月，基础 55,170 次队列操作。上一轮整个账号 24 小时 CPU 480,801 毫秒；30 天基线约 1,442 万毫秒，再加每日任务 184 万毫秒（每次 100 毫秒假设）和登录活动预留 300 万毫秒，约占 3,000 万包含额度的 64%。这是预算，不是迁移实测或准确账期账单。日志只记录任务标识、结果分类、耗时和必要计数，不记录凭据、手机号、验证码、票据或原始上游回复。部署后检查实际 CPU/请求及上游失败分类。

## 验收和回滚

离线测试必须覆盖消息重复/丢失窗口、结果回写失败、租约过期、凭据变化、跨日与暂停；登录持久化重建、过期、票据重放、并发、超时、验证码错误恢复；SDK 队列容量/超时/取消；活动互斥及未知结果确认。workerd 本地集成使用模拟上游，不发送真实短信，不用真实账号制造压力。

部署先备份 D1/Worker 配置和当前 VPS 镜像，应用新增字段/索引，发布未启用的执行端和独立令牌服务，验证绑定与只读检查；先切登录/活动，再停旧任务领取并排空已领取任务，启用 Queue 消费。必要时暂停新消费者、等待在途任务停止，切回网站旧路由和旧 runner。新增列可以留存，回滚不回退或删除用户数据。切换前已有的短期登录挑战需在原服务继续完成或在 5 分钟后自然过期。

故障恢复验证补充：已发布但一小时仍未领取的任务按原账号、日期及状态约束更换投递标识后重投，防止队列和死信投递都耗尽造成永久排队；正常投递不逐分钟重复发送。停用每日执行时仍可记录死信失败，不能因此执行账号业务。新增回归测试覆盖两条路径。
