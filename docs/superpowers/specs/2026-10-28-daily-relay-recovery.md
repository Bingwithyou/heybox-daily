# 每日任务 Worker 转发与补跑

2026-10-28 用户要求尽快恢复 VPS 403 后的每日任务，并在推荐方案确认时授权按最快路径实施、部署和补跑。

## 已核实的原因

同一个已签名任务列表请求，VPS 直连返回 OpenResty 403，现有 `heybox-login-relay` Worker 返回 200 JSON。出口拦截是强相关判断，上游具体规则未知。当前 Runner 依赖 Node 子进程，完整迁移到 Workers 需要另行重构，故采用现有转发架构。

## 已批准范围

- Worker 增加每日签到、帖子/游戏/评价选择和分享上报的固定 origin、path、method 白名单；不接受任意目标，不跟随重定向，不缓存或记录敏感请求。
- 新增 Runner `DAILY_TRANSPORT=worker` 开关，复用现有转发 URL 和密钥；默认 `direct`，错误配置拒绝启动。登录和活动的既有路径不变。
- 保留 VPS 的签名、凭据解密、租约、逐步暂停检查、读取真实状态、结果回写和每日去重。失败不在传输层重试或切换出口。
- 正式每日任务并发降为 1。先用一个未完成的有效托管账号验证，成功后分批补跑今天尚未完成的账号。403、429 或明确限流出现时停止后续批次并调查。
- 已完成步骤跳过，暂停、删除及登录过期的账号不纳入补跑；不会伪造完成记录或绕过任务的最终核验。

## 关键边界与回滚

白名单必须同时检查完整 origin 和方法，尤其 `data.xiaoheihe.cn/account/data_report/` 只能 POST，不能将 API 主机的路径规则套用到其他主机。Worker 错误保持 HTTP 状态，服务密钥不转发上游。Worker 不新增数据库、队列或 Cron。

回滚恢复旧 Worker 版本及 Runner 镜像、环境备份，或关闭每日转发开关；不回滚用户任务结果。Cloudflare 出口可用性不保证永久稳定，补跑以实际上游结果为准。

本次不 commit、push 或创建 worktree。
