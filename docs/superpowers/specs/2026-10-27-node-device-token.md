# Node.js 设备令牌

## 已确认范围

用户要求先验证真实短信发送和完整登录，通过后用 Node.js + jsdom 替换 Chromium；最终选择在新登录时随机生成一次浏览器指纹，后续保留设备令牌和设备 ID。2026-10-27 已在 Oracle Linux ARM64 上使用 jsdom 27.0.1 和 fingerprint-generator 2.1.89 完成官方令牌签发、正常腾讯人机验证、短信发送、验证码登录、任务列表及签到状态读取。随机指纹没有消除人机验证，不能承诺降低风控。

## 设计

- 保持 `getDeviceToken()`、登录配置和站点接口合同。仅替换令牌初始化的运行环境；APP 版本、Android 型号/系统和原生签名不变。
- 在函数调用时动态加载 jsdom 和 fingerprint-generator。生成一套 Linux 桌面 Chrome 指纹，统一 navigator、screen、窗口尺寸和 HTTP User-Agent；不在请求之间更换，也不实现 Canvas/WebGL 或修改 webdriver。
- 使用官网公开组织、应用和公钥配置，下载官网 SDK。执行前检查已验证版本的 SHA-256，防止未经审查的第三方脚本在 Node.js 中运行；官方更新导致校验失败时明确报错，维护者复核后更新摘要。SDK 不随仓库分发。
- 在临时 jsdom Window 中执行原始 SDK，只有 `B` 前缀、89 位令牌可返回。`D` 前缀的待处理数据不能视作成功。下载、脚本执行、等待令牌均有超时；成功和失败都关闭 Window，保留失败阶段和安全诊断。
- 指纹仅在初始化期间驻留内存，不增加数据库字段或逐账号存储；既有 `device_id` 和签发令牌继续随会话保存。
- 删除 Playwright Core、Chromium 安装和相关环境变量。日常 runtime 镜像继续不装登录依赖；login/runner 目标保留 Node.js 依赖，兼容既有命令和 compose 服务。

## 审查结论与验证边界

`brainstorming` 与 `grill-with-docs` 已检查 SDK 更新、动态依赖加载、脚本执行超时、网络失败、异步初始化、错误令牌、资源释放、配置兼容性和镜像回滚。SHA-256 固定会让 SDK 更新后的新登录暂时失败，已有凭据及日常任务不受影响。jsdom 不提供完整浏览器渲染或安全沙箱，来源校验和现有登录子进程边界保留。

同机离线各 5 次冷启动：默认 jsdom 中位 1121 ms / 峰值 RSS 中位 116.2 MiB；随机指纹 1428 ms / 155.5 MiB。该测试不含网络和短信耗时，不是长期容量测试。

## 验收与回滚

验证令牌等待/错误/超时、同一初始化内指纹一致、不同初始化独立、现有登录和凭据加密兼容性；完成仓库所需检查和三个镜像目标构建。最终 runner 镜像中不存在 Chromium/Playwright，实际官方 SDK 仍可签发令牌。生产发布前保留旧镜像及部署配置，可切回旧镜像恢复浏览器实现；不回滚用户已有的倒计时修复或 4 GiB 内存设置。

## 登录并发调整

用户追加要求评估 runner 并发。相同 VPS、2 核容器实测 2 路令牌初始化全部成功，批次 2609 ms、容器峰值 333.2 MiB；4 路全部成功，单请求 2903–6651 ms、容器峰值 495.5 MiB。将登录操作共享上限从 2 调为 4，范围仍覆盖新登录、人机验证继续、短信验证；等待用户输入不占执行名额，超过上限仍返回繁忙，不增加排队或重试。日常任务串行及短信限额不变。测试覆盖第 5 个操作被拒绝、不同登录步骤共享上限和失败后释放名额。该短测不证明长期吞吐或上游限流改善。用户已明确批准以 4 并发与 jsdom 一起部署，等待队列及执行中的登录步骤空闲后切换。
