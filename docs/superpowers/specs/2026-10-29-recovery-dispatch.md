# 补跑即时派发

用户已批准：实际执行并发保持 8，补跑脚本维护最多 32 个未结束任务；每批入队后通过受现有服务鉴权保护的 Web 内部入口唤醒执行器；检查间隔缩短为 4 秒。部署后在当前线程观察 20 分钟，报告完成速度、首次失败与最终失败、剩余任务及预计完成时间。

Web 新增 `POST /internal/executor/wake`，复用 `notifyRunner`。鉴权失败返回 401，错误方法返回 405；执行器接受唤醒返回 204，唤醒失败返回 503。不携带用户数据，不直接执行任务。204 只证明唤醒被接受，实际投递及完成通过 D1 和四项任务结果确认。

临时脚本继续使用原候选清单、状态比较更新、日志对账、任务令牌与租约机制。仅在实际入队后每批唤醒一次，启动恢复时也唤醒已有任务。唤醒失败记录后交由原有 Cron 恢复，不重复重置任务。保留凭据失效、取消、最终失败、15 分钟无进展和跨日边界。

Queue 继续每批 1 条、最大执行并发 8，消费者自动扩缩容，因此不承诺每秒满载。正常登录、用户重试、每日任务流程与数据库结构不变。停止追加不取消已经排队的任务。
