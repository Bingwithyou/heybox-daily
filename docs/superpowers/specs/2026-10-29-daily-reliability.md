# 每日任务执行可靠性与 00:30 调度

> 执行次数和退避规则已由 `2026-10-29-daily-retry-budget.md` 更新为每天最多 5 次。

用户已批准设计并授权验证后部署正式环境。改进现有每日主流程，不另建补跑系统、后台脚本或新管理页面；实际并发继续为 8。

- 每日批量任务从北京时间 00:30 开始，Cron、创建门槛、下一次时间、页面说明同步。登录、恢复托管和手动执行维持即时处理，未获新授权的历史失败不重置。
- 每轮自动执行最多 3 次。网络、超时、HTTP 5xx/408 失败依次等待 5、20 分钟；429 或明确业务限流优先采用有效 Retry-After，无提示时依次等待 15、30 分钟。加入 0–60 秒随机延迟。所有重试都在原任务内，自动路径不清零次数；跨日停止。手动重试现有授权和限频保持。
- 明确凭据失效停止并要求重新登录。验证码、协议/格式变化及其他不可分类错误不按短暂网络故障反复执行。兼容已有执行端缺少新诊断字段的结果，保守按既有 upstream/timeout 分类处理。
- 每次先读取实态，只执行未完成项目；结束重新读取签到和三项任务。成功必须带四项各唯一且 finish 的快照。写请求结果丢失先读取实态，读失败不继续写；保留 uncertain 和未知奖励，不制造成功或零收益。
- 逐次执行在 D1 留存独立记录，使用任务 ID、尝试 ID 关联起止、错误、阶段和确认结果。领取与开始记录原子写入，结果与尝试终态原子提交，消息重复不额外计次。租约失效的尝试标为结果未知，旧执行不能覆盖新结果。
- 错误数据只包含接口路径、HTTP 状态、经过校验的业务代码、类别、耗时、执行阶段、重试时间；不记录 Cookie、凭证、查询串、原始上游消息/响应或异常 cause 内容。保留最初错误和失败后的复查错误。成功日志保留概要，错误日志足以定位阶段。
- 原任务页只增加异常说明与预计重试时间。不会展示详细内部日志或新增后台。

验收包括时间边界、完整回读、状态写入丢失、重复消息、暂停/重登/跨日、分类退避、重试次数上限、错误脱敏、线上调度与并发配置。00:01 高峰导致限流仍属待验证假设。
