# 日常任务并行实施计划

对应设计：`docs/superpowers/specs/2026-10-27-task-concurrency.md`。

1. **先固化回归场景。** 扩展 `apps/runner/test/queue.test.ts` 验证 8 并发上限、完成即补位、重复通知不超额、独立回传重试、停止排空和停止期间的领取响应；保留现有串行/空闲兼容测试。复用 `apps/web/test/store.test.ts` 增加多个账号领取、暂停/重新登录的租约隔离场景。观察新增测试先失败。
2. **实现单一调度器。** 修改 `apps/runner/src/queue.ts`、`main.ts`、`.env.example`，增加配置验证和有限执行集合；任务回传重试独立等待；停止时等待在途工作，不改租约与接口合同。
3. **补充可核查日志。** 在现有 worker/process 日志路径中增加日常任务耗时、结果及有限失败分类，覆盖日志脱敏与上游限流分类；不记录账号、密文、设备或上游原文，不修改公开错误枚举。
4. **修改任务页提示。** 仅调整 `apps/web/src/routes/tasks.tsx` 右上角状态分支，沿用轮询、颜色与排版。检查排队、运行、完成、暂停及窄屏展示，不新增复述 JSX 的测试。
5. **离线容量验证。** 增加可重复执行的隔离基准脚本，使用实际 runner 子进程及真实签名流程，把所有网络替换为本地模拟响应；运行 1 / 4 / 8 并发，报告完成数、总时长和进程树峰值内存。失败必须定位，不能用模拟结果宣称真实上游通过。
6. **相关验证与文档。** 更新 `docs/hosting.md`；运行 runner 类型检查及完整测试、web 测试/构建/类型检查/lint/格式检查/本地集成测试。根目录构建会更新被忽略的 dist；web 构建生成被忽略的产物，构建前检查本地测试密钥不会进入产物。Docker 不可用则明确记录，不安装或启动远程资源。

命令使用 Node.js 24 与现有依赖。优先直接执行已安装的 TypeScript、Vite+ 和 Node 测试入口，避免系统 pnpm 的版本切换问题。集成测试只使用临时本地 D1/Worker 和模拟 runner。实际发布及真实上游并发验收需对应明确授权。

通过条件：从未超过 8 个在途任务，8 个任务之间可独立补位和回传；同账号不会重复领取；退出不遗失已领取任务；空闲仍约 48 次/天；页面运行状态准确；离线测试不访问真实账号。

风险与回滚：同 spec。生产机器与上游并发上限仍需实际观测，本地基准仅证明实现与本机资源表现。

## 验证结果

2026-10-27，Apple M3 Pro / Node.js 24.22.1，每档八个合成账号，执行完整四项任务；所有上游请求使用 50 ms 模拟延迟，保留生产任务等待。三档共 24 个任务全部完成，每档 312 次模拟请求（含心跳）。

| 并发 | 八个账号总耗时 | Node 进程合计峰值 RSS | Node 累计 CPU 时间 |
| --- | --- | --- | --- |
| 1 | 122.94 秒 | 313.1 MiB | 3.60 秒 |
| 4 | 30.78 秒 | 624.9 MiB | 2.13 秒 |
| 8 | 15.46 秒 | 1039.8 MiB | 1.98 秒 |

峰值 RSS 为每 100 ms 采样的基准主进程和实时 Node 子进程之和；CPU 时间含主进程采样开销，不含 `ps` 子进程。串行档持续时间更长，采样开销更多，不能用 CPU 总时间差推断并行减少了签名计算。8 并发耗时约为串行的 1/7.95；未测试真实上游及 VPS，也未叠加四路登录。

- runner 完整测试 40 项通过，web 完整测试 50 项通过；runner/web 类型检查、web build、lint、format:check 及本地 D1/Worker 集成测试通过。
- 新增测试先确认旧实现不能达到八并发，再验证并行、补位、独立重试、停止等待和账号租约隔离；HTTP 429 与日常日志脱敏测试通过。
- 本地浏览器以隔离测试账号验证：排队 → 执行中（绿色圆点）→ 完成后恢复下次执行时间 → 暂停后隐藏下次执行。复用原有自动刷新，没有重载页面。
- 构建仍有已有 CSS sourcemap 提示，不影响成功结果。当前机器无 Docker 命令，未进行容器验证。未提交、推送或部署。
