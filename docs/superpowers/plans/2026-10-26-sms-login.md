# 短信登录实施计划

## 1. 登录协议与配置保存

涉及 `src/client.ts`、`src/config.ts`、`src/login.ts`、`src/types.ts` 和 `test/login.test.js`。

- 扩展原生请求支持查询参数和表单，复用现有签名与请求处理。
- 复用 Android Base64、Node RSA 加密，实现发送验证码、兑换 APP 会话和响应校验。
- 从空会话开始，验证真实登录后才以临时文件加原子重命名保存配置；不持久化手机号和验证码。
- 先加入失败用例：无旧凭据、请求格式、验证码/账号异常、读取状态失败不覆盖原文件、保存权限。
- 验证：`pnpm test`、`pnpm typecheck`。测试只使用本地假数据，不发送短信。

## 2. 官网设备令牌与 CLI

涉及 `src/device-token.ts`、`src/cli.ts`、`package.json`、`pnpm-lock.yaml`。

- 使用已在 VPS 验证的官方网页和 SDK，在临时 Chromium 上取得令牌，结束时关闭浏览器。
- 增加命令行登录交互和资源检查，错误不回显敏感请求，不自动重发验证码。
- Pin Playwright Core 版本并保留现有 TypeScript/pnpm 构建方式。
- 用注入式测试覆盖交互顺序及失败路径；真实浏览器初始化通过 Linux/VPS 验证。

## 3. 镜像和使用说明

涉及 `Dockerfile`、`compose.yaml`、`.github/workflows/ci.yml`、`README.md`、`docs/usage.md`。

- Docker 增加 `runtime`、`login` 目标；仅登录目标包含 Chromium 和 Playwright。
- Compose 增加显式调用的 `login` 服务及交互输入、可写配置挂载。两个服务共享运行锁，修复宿主机私有文件权限问题。
- 文档说明首次资源准备、短信登录、日常任务、重新登录及浏览器依赖边界；保留赞助。
- 本地验证构建及帮助输出。VPS 使用隔离测试目录运行正式命令，检查保存配置和轻量镜像读取结果，不新增定时任务。

## 4. 推送与 CI

- `git diff --check`、必要测试和两个镜像构建完成后，检查所有待提交文件及实际凭据值，排除 `private/`、`.research/`、资源、日志及探针。
- 使用仓库已有 local GitHub identity 提交；将获准分支同步到配置的各 remote。
- 确认 GitHub Actions 在新提交启动并读取最终结果。

## 风险与回滚

官网或 SDK 改版会影响新登录；已保存配置和日常流程保持独立。新登录失败不得修改旧配置。回滚时移除登录服务、相关模块和依赖，保留账号配置、已完成的 TypeScript 迁移、README 风格和赞助改动。推送已获授权；不创建 PR、不修改现有 VPS 服务、不安装 cron。

验证命令会生成 `dist/`、依赖目录和 Docker 镜像；这些均不提交。真实登录会发送短信并创建新会话，仅对用户提供的账号操作。
